# Ordifile v0.6.0 — Chromatography format and mapping updates

This release ships the previously merged development work since v0.5.1 and updates
the PyPI publishing workflow to the fixed PyPA action. No additional instrument or
vendor-export data were collected or validated for this release. The scientific
claims below remain limited to the existing repository evidence.

## Scientific capabilities and limits

- **YoungIn YL-Clarity PRM:** Experimental, opt-in, marker-based `calculated_area`
  on the exact validated 9.0.1.19 and 9.1.0.76 profiles when the required marker and
  processing-table fingerprints match. The controlled comparison matched 304 of
  305 eligible areas at their vendor-export display precision, after excluding
  42 rows from channels with unsupported timed events. The calculation declines
  such channels and leaves Signals unchanged. It is not the proprietary vendor
  integration algorithm, does not export calculated Height, and does not claim
  general vendor equivalence. Use a supported official Result export for explicit
  values, especially manually adjusted runs.
- **Shimadzu LabSolutions GCD:** Read the stored peak table on the bounded,
  validated 5.82 profile when the expected stream is present. Retention, peak
  boundaries, Area, and Height are stored values, not new integration; Area and
  Height units remain unresolved.
- **Shimadzu GCMSsolution QGD:** Read stored mass-chromatogram peak rows in the
  supported CFB v3 and v4 generations, including the stored compound name when
  present. Populated tables have been checked for internal consistency but have
  not been compared with a same-run GCMSsolution export; Ordifile marks those
  peak values unvalidated against the vendor export. The adapter does not claim
  spectra export, quantitation, or unknown profile support.
- **Shimadzu LabSolutions LCD:** Read signals from the observed TTFL acquisition
  channels and TLM single-trace architecture. Unsupported architectures (including
  QTFL) and ambiguous documents are refused. The physical intensity unit remains
  unresolved; no peaks, spectra, or compound identities are inferred.
- **Agilent ChemStation:** The experimental `.CH` internal v179 reader emits
  retention and response signals; the existing v181 reader remains structural
  only. Observed v179 scale agreement with paired reports is within 0.5%, not exact;
  unrecognized units are not assigned and no peak table is inferred. For recognized
  `.D` runs, audit-log the known bookkeeping members and join exactly one readable
  signal with exactly one explicitly mapped peak table when unambiguous. Otherwise
  keep the inputs separate and report the ambiguity; this is not automatic peak
  discovery or support for arbitrary `.D` layouts.
- **ANDI/AIA chromatography CDF:** Read supported netCDF-3 chromatography elements,
  including file-declared units and present standard-defined peak fields. Missing
  or nonuniform sampling declarations and unrecognized retention units are refused.
  No new signal integration is performed.
- **Explicit table mapping:** Accept UTF-16 text with a byte-order mark and
  headerless delimited sources with an explicitly selected mapping. Headerless
  worksheets and automatic routing of headerless mappings are not supported.
- **Official Result acquisition:** Adds the provider boundary and provenance-aware
  merge foundation. No production vendor provider is registered or shipped, and
  there is no automatic vendor software invocation in this release.
