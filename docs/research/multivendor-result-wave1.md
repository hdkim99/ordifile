# Multi-vendor result expansion: Wave 1

- Research and access dates: 2026-08-19 through 2026-08-20
- Scope: one-run GC/CDS result and peak-table exports with explicit retention time
  and peak area
- Manufacturers researched: Thermo Fisher Scientific, PerkinElmer, SCION
  Instruments, LECO, and Bruker
- Decision: the exact LECO ChromaTOF 4.72 GCxGC profile remains the accepted
  Experimental baseline. A bounded 2026-08-20 acquisition pass found lawful
  machine-readable Chromeleon and TASQ near-misses, but no implementation-ready
  one-run 1D GC Result profile. All Wave-1 1D targets therefore remain blocked or
  evidence candidates.

This matrix records exact software/export profiles rather than claiming support for a
manufacturer. A profile enters the public format list only after a lawful actual fixture,
bounded detection, explicit finite RT and area mapping, complete source-row comparison,
workbook regression, and privacy/license review all pass.

## Status vocabulary

- `RESEARCH_ONLY`: official product or export evidence exists, but the exact profile is
  not ready for intake.
- `BLOCKED_FIXTURE`: export capability is documented, but no lawful actual fixture with
  a stable grammar is available.
- `EVIDENCE_CANDIDATE`: a potentially lawful artifact exists but its table, units,
  privacy, or profile identity still requires bounded intake.
- `IMPLEMENTATION_GO`: one exact profile has passed fixture, grammar, scientific,
  privacy, and legal intake and may receive an adapter in a separate PR.
- `EXTERNAL_ORACLE_ONLY`: observed bytes may inform research but their file-specific
  redistribution permission is unresolved.
- `ADR_REQUIRED`: lawful actual evidence exists, but the canonical model cannot retain
  its scientific coordinates without an explicit architecture decision.
- `EXPERIMENTAL_GO`: an exact adapter and all evidence, scientific, privacy, and legal
  gates pass. The exact LECO ChromaTOF 4.72.0.0 GCxGC profile has this status.

## Evidence details

### Thermo Fisher Scientific / Chromeleon

The official [Chromeleon 7.3 Functional Specifications](https://docs.thermofisher.com/api/khub/documents/fcN7nLsBEBuVy1IExPb1rw/content)
define ASCII Result Text export and report variables for retention time, area, height,
peak number/name, peak start/stop, chromatogram channel, detector, and signal unit. The
[Chromeleon 7.3.2 Quick Start Guide](https://docs.thermofisher.com/r/Chromeleon-7.3.2-Quick-Start-Guide/1561513995v2)
shows that an export can cover an injection, sequence, or multiple sequences and that
the report template and channel are selected at export time. Those choices prevent a
generic `Chromeleon TXT` claim: Ordifile needs one actual one-injection export from one
fixed template before it can define headers, delimiter, encoding, units, or cardinality.

A separate [Dryad CC0 dataset](https://datadryad.org/dataset/doi%3A10.5061/dryad.b5mkkwhpg)
provides a lawful machine-readable Chromeleon 7.2 GC-MS workbook. The selected workbook
is 224,782 bytes with SHA-256
`e59731fe0a8f4f95a506da2c7ef7ec9ac7c9d38d5fcf7620f5d44aa88cb62490`; inspected
result sheets contain `Peak Name`, `Ret.Time`, `Peak Area`, and `Amount`, with minutes
and counts-times-minutes units. It is a multi-injection batch workbook with derived
research sheets, not an untouched one-injection Result Text export. The current
one-source/one-sample adapter contract cannot represent it without a separate accepted
multi-sample decision, so it remains a profile-specific near-miss rather than an
implementation fixture.

### PerkinElmer

The official [SimplicityChrom product page](https://www.perkinelmer.com/category/simplicitychrom-cds)
and vendor-hosted
[Data Review export material](https://perkinelmer.widen.net/view/video/axzhwdb82x/Exporting_Data_from_Data_Review_Source.mp4?u=hqlp4q&use=zlgun)
establish result generation plus CSV/XLSX export. The official UI shows `Peak Name`,
`Retention Time (min)`, `Area (mAU-s)`, `Height (mAU)`, and `Area Percent (%)`, but it
does not open or publish the emitted bytes. Delimiter, quoting, encoding, line ending,
producer marker, exact software version, and row grammar therefore remain unresolved.
SimplicityChrom, TotalChrom, and Chromera remain separate profile families.

The [Dryad TotalChrom dataset](https://datadryad.org/dataset/doi%3A10.25338/B8C35T)
is a lawful CC0 evidence candidate for a TotalChrom Navigator 6.3.2.0646 / Clarus 500
GC-FID PDF report. The inspected calibration-standard candidate has two finite peak
rows with `Time [min]`, `Area [uV*sec]`, and `Height [uV]`, but also contains
privacy-bearing metadata. It remains external-only grammar evidence. This cycle does
not add a PDF parser; an exact lawful machine-readable export is still required.
Third-party mirrors of the TotalChrom workstation guide describe configurable ASCII
reports using `.TX0` and optional `.TX1` through `.TX6` files, while a lawful
[CC BY protocol](https://www.protocols.io/view/gas-chromatochraphic-detection-of-sesquiterpenoids-kj2cuqe.pdf)
describes ASCII/CSV export capability. Neither source supplies an untouched generated
one-run file, so they are grammar evidence only and do not authorize an adapter.

### SCION Instruments

The official [CompassCDS product page](https://scioninstruments.com/products/compass-cds/)
and [2022 brochure](https://scioninstruments.com/wp-content/uploads/2020/11/Compass-CDS_Brochure_2022_Stg06.pdf)
describe processing/reporting, an encrypted all-in-one `.DATA` container, and Print
Manager conversion of chromatogram results to ASCII, Excel, and AIA. Ordifile will not
bypass `.DATA` encryption. The export grammar remains blocked until a lawful actual
ASCII or Excel Result fixture establishes exact headers, units, and profile identity.
The acquisition pass inspected official SCION media and public code/data repositories;
it found no such bytes. A public legacy Galaxie manual documents configurable output,
but it cannot establish the current CompassCDS producer or grammar.

### LECO

The official [ChromaTOF-GC legacy page](https://www.leco.com/documents/chromatof-gc-legacy-version/)
confirms automatic CSV export. The peer-reviewed
[Maui-VIA profile description](https://pmc.ncbi.nlm.nih.gov/articles/PMC4301187/)
records a ChromaTOF 4.50.8.0 one-dimensional CSV peak-list grammar with `Name`,
`Retention Index`, `Area`, `R.T. (s)`, signal-to-noise, and integration boundaries.

The pinned MSDK repository contains two original 1D ChromaTOF report variants:
[`chromatof-1D-sample.csv.gz`](https://raw.githubusercontent.com/msdk/msdk/a1dbc365194c6e054e6a19a207c26186be7cdb92/msdk-io-chromatof/src/test/resources/full/1D/chromatof-1D-sample.csv.gz)
is 502,551 compressed bytes (SHA-256
`c743eaf1d81984c8dbcdb8bbeea00e91806d323161b97db1dc4b589b2e50d9c4`) and 2,097,892
decoded bytes (SHA-256
`c17036a7600dab8c70fdf33c8a59f380de8c43dfa45c898fd7ee77bdb9295d89`);
[`chromatof-1D-sample-unmapped.csv.gz`](https://raw.githubusercontent.com/msdk/msdk/a1dbc365194c6e054e6a19a207c26186be7cdb92/msdk-io-chromatof/src/test/resources/full/1D/chromatof-1D-sample-unmapped.csv.gz)
is 502,794 compressed bytes (SHA-256
`49aa5ea5ea6df90cd8454ee7e34067e633a4784c966db4de72292230988061d9`) and 2,100,285
decoded bytes (SHA-256
`0a96806495971321b71eb70fd9ea136a08cc4602d472c81a9a993ab5c78768a8`). The 16- and
17-column variants each have 594 rows with explicit finite RT, area, and height. The
repository's top-level LGPL-2.1-only OR EPL-1.0 code license does not supply an
unambiguous file-specific grant for these externally provided reports. They are
therefore external research oracles only. No fixture bytes or implementation code are
copied.

The lawful [Dryad ChromaTOF 4.72 dataset](https://datadryad.org/dataset/doi%3A10.5061/dryad.k98sf7m8m)
establishes a real tab-delimited GCxGC profile with RT1, RT2, area, and height. The
exact dataset README is 10,040 bytes with SHA-256
`07e1d8becce25ed0b5c5a191e99d4f514d79c978a0b28e0a7e6198c374ef71ad`; its file
structure section defines Area and Height as Arbitrary Units (`AU`) for these exported
tables. This dataset-level unit evidence does not generalize to another ChromaTOF
version or export profile. The
exact non-human model-mixture member passes the full 100-row external comparison and
supports the narrowly bounded Experimental adapter. Its source archive and unrelated
human-derived subsets are excluded from Git, CI extraction, packages, workbooks, and
artifacts. ChromaTOF Sync and Sync 2D are separately
described by the official [Sync product page](https://www.leco.com/products/chromatof-sync/)
and must not be conflated with the legacy single-run CSV profile.

### Bruker and SCION lineage

Bruker's official [2014 divestiture notice](https://ir.bruker.com/press-releases/press-release-details/2014/Bruker-Completes-Divestiture-of-its-Gas-Chromatography-Product-Lines/default.aspx/1000/)
states that its GC and GC single-quadrupole product lines moved to the business that
became the current SCION lineage. Current Bruker GC-TQ and TASQ software require
their own producer/profile fixture. Legacy Varian/Bruker exports must not become both
a SCION adapter and a broad Bruker adapter without exact producer evidence.

Current Bruker material establishes configurable TASQ LIMS columns and
measured-retention-time/area fields, but does not establish the emitted LIMS container
or publish a one-analysis EVOQ GC-TQ file. A lawful
[CC BY 4.0 TASQ workbook](https://zenodo.org/records/17750282)
contains actual area and retention-time tables, but its provenance is UHPLC-QTOF-HRMS,
not GC. Separately observed multi-analysis `Global Results` CSV files lack embedded
Bruker/TASQ/version markers and have no file-specific fixture grant. Both are useful
profile oracles only; neither can justify a current Bruker GC adapter.

## 2026-08-20 acquisition pass

The bounded search covered vendor manuals, product pages, download and tutorial assets,
official sample media, Zenodo, Dryad, Figshare, DataCite, MetaboLights, Mendeley,
journal supplements, institutional and government repositories, and authenticated
GitHub/GitLab code and repository search. Searches combined product names with exact
RT/area/height headers and documented result extensions rather than relying on
filenames. Candidate bytes were opened before classification; search-result snippets
were not accepted as evidence.

No Wave-1 target produced an implementation-ready lawful one-run machine-readable 1D
GC Result fixture. The minimum next acquisitions are therefore:

- Chromeleon 7.3.x: one untouched one-injection `Text format (Results) (.txt)` export
  from one fixed report template and channel;
- SimplicityChrom 3.1: one untouched one-injection Result Set Review CSV, or XLSX if
  CSV is unavailable;
- TotalChrom 6.3.x: one untouched one-run `.TX0`/ASCII-delimited Result from one fixed
  report template and channel;
- CompassCDS: one untouched one-run Print Manager ASCII or Excel Result export;
- ChromaTOF 1D: one untouched one-run CSV with `R.T. (s)`, `Area`, and `Height`, plus
  an explicit lawful controlled-use basis; and
- current EVOQ GC-TQ/TASQ: one untouched one-analysis LIMS export in its original
  emitted container with measured RT and integrated GC area.

A non-human standard, calibration, or model-mixture run is preferred. Any owner-supplied
file remains local-only, is privacy-scanned before parsing, and is represented publicly
only by a sanitized source identity and bounded evidence.

## Implementation gate

The next adapter PR may start only when one exact profile satisfies all of the following:

1. an actual vendor-generated fixture has a lawful-use basis and a classified
   redistribution boundary;
2. manufacturer, software/version boundary, and export profile are evidenced;
3. one input represents exactly one sample/run, or a separately accepted multi-sample
   architecture exists;
4. RT and area are explicit, finite source fields rather than inferred quantities;
5. RT and area units are preserved when stated and remain unresolved when absent;
6. a bounded signature distinguishes the profile from generic CSV/TXT/XLSX/PDF;
7. every source row is compared with canonical `PeakRecord` and workbook output;
8. malformed family members remain structured vendor failures instead of falling
   through to a generic adapter;
9. privacy-bearing values are excluded from public fixtures, logs, workbooks, and CI
   artifacts; and
10. no proprietary vendor code, DLL, executable, or protected-format bypass is used.

The current implementation order is therefore evidence-driven, not the manufacturer
list order. The lawful ChromaTOF 4.72 GCxGC dual-retention profile remains the current
implemented baseline because its exact fixture, grammar, scientific values, privacy
review, and canonical architecture are established. No new 1D adapter is authorized
by the 2026-08-20 pass. The TotalChrom PDF and all other near-misses remain intake
evidence only; this cycle does not implement a PDF parser or a multi-sample workaround.

## Explicit non-decisions

- The LECO support claim is limited to the exact adapter and selected 100-row
  non-human external comparison; it is not a broad LECO or ChromaTOF claim.
- No broad manufacturer support claim is made.
- No 2D retention coordinate is discarded or silently mapped to metadata/channel.
- No MSDK or other reference implementation code is copied or translated.
- No raw binary reverse engineering is required before a lawful Result profile.
- No version number, release, tag, or public standalone artifact is authorized.
