# External fixture policy

- Effective date: 2026-08-16
- Applies to: real instrument data used for format research or optional integration
  validation.

## What may be committed

- Synthetic fixtures generated by repository scripts.
- Redistributable derived fixtures only when the source license, attribution,
  modifications, privacy review, exact source digest, and derived digest are recorded.
- Small unchanged real fixtures only after explicit redistribution and privacy review.
- Machine-readable manifests, fetch tooling, tests using synthetic malicious archives,
  and aggregate reader results.

The default remains conservative: real proprietary Raw files stay external even when
redistribution appears permissible. No manufacturer SDK, DLL, executable, method with
private paths, or user Raw file may be committed.

## External-only material

Files remain outside Git when they are large, require creator attribution that cannot
be represented under repository privacy rules, contain names or machine-local paths,
have uncertain third-party rights, or are useful only for research. The ignored paths
are `.external-fixtures/`, `.research-downloads/`, and `fixture-cache/`.

External-only does not mean unsupported. It means that a maintainer may fetch the exact
artifact for an explicitly approved research or optional-integration run. It never
turns a live URL into a default test dependency.

## Integrity and size policy

- Every artifact has an exact HTTPS source, allowlisted redirect hosts, byte size, and
  SHA-256. Provider MD5 may be recorded but never replaces SHA-256.
- A changed digest is a hard failure; the script deletes partial data and does not
  select a mirror or accept replacement bytes.
- Default download limit: 256 MiB. Explicit `--allow-large` limit: 2 GiB.
- Default uncompressed ZIP limit: 2 GiB. Large-mode limit: 8 GiB.
- Default ZIP member limit: 10,000. Large-mode limit: 100,000.
- Per-member compression ratio limit: 100:1.
- A manifest may be stricter but cannot raise these bounds.

Selected-file tree hashes include a versioned prefix, normalized sorted relative path,
byte length, and exact file bytes. The algorithm is implemented and regression-tested
in `scripts/fetch_external_fixture.py`; changing it requires a schema version change.

## License, attribution, and privacy

The canonical dataset page and its actual license or government terms must be opened.
Public download access alone is insufficient. The manifest records the redistribution
grade, attribution, verification date, and reader evidence. A download requires the
user to acknowledge the manifest's exact license identifier.

Before adoption, inspect filenames and file content for names, email addresses, user
profiles, absolute paths, hostnames, serial numbers, clinical identifiers, and free
text. A fixture with unresolved privacy review is ineligible for automated use. Raw
member names must not be printed in public CI logs.

`ACCEPT_CONTROLLED_CI` is a narrow exception for an artifact whose redistribution is
explicitly permitted but whose internal content contains personal or machine-local
text. It requires owner-only manual dispatch, a private job-local temporary directory,
no content logging, no cache or artifact upload, no default-CI access, and unconditional
deletion. This grade does not permit committing the file or exposing its metadata.

## Fetching and extraction

The maintainer-only fetch script is not an Ordifile product command and is not installed
as a console entry point. It:

1. strictly validates the versioned manifest and license acknowledgement;
2. accepts HTTPS and only declared redirect hosts;
3. streams into a private temporary file with byte and SHA-256 limits;
4. verifies the entire archive inventory before extraction;
5. rejects absolute, parent-traversing, Windows-ambiguous, duplicate Unicode/casefold,
   encrypted, linked, device, FIFO, and compression-bomb members;
6. streams only declared regular members into a temporary directory;
7. verifies the selected tree digest before atomic finalization; and
8. removes partial state after failure.

It never executes archive content or calls vendor software. ZIP is the only format
automatically extracted in version 1. A 7z artifact is checksum-verified download-only;
shelling out to `7z x` is not allowed. A direct raw file is download-only.

For the committed BSEE declaration, a maintainer can make an explicit local-only fetch:

```bash
python scripts/fetch_external_fixture.py \
  docs/research/external-fixture-manifest.json \
  --cache-dir .external-fixtures/gc \
  --accept-license BSEE-Public-Information-2026-08-16
```

The script displays the source, terms, attribution, and expected digest before any
download. This command does not install a parser or make the fixture part of default CI.

## CI policy

Default pull-request, push, and scheduled CI performs no external fixture download.
Tests use local synthetic HTTP responses and malicious synthetic archives to exercise
checksum, redirect, traversal, alias, link, bomb, and cleanup controls.

The Agilent v181, Shimadzu LabSolutions 5.82 GCD, and Shimadzu GCMSsolution QGD
adapters each have an owner-repository external integration workflow. All are
`workflow_dispatch` only and use the shared
self-hosted DGX runner with read-only repository permission, `RUNNER_TEMP`, and no
Actions cache or artifact upload. Each deletes its fixture cache in a final cleanup
step. The Shimadzu workflows additionally follow `ACCEPT_CONTROLLED_CI`: each fixture's
embedded personal and local-machine text is never printed or exported. Pull requests
and default CI never download either fixture. Scheduled use requires a separate
decision covering stable access, automated-use permission, privacy, cost, and size.

## Removal and replacement

Remove or disable a fixture when its license changes, privacy concerns emerge, the
source disappears, bytes change, or the expected reader result is disproved. Do not
silently replace it. Record the old identifier and digest, the reason, the replacement
identifier and digest, and whether prior support claims remain valid. A removed
fixture can invalidate a format's “verified” status until a replacement passes the
same tests.
